1 Executive Overview & Problem Space

ShagunShopping is a high-volume cosmetics, skincare, and luxury wellness e-commerce platform serving customers across India. The system handles volatile consumer demand patterns—characterized by high-intensity flash sales, seasonal festive traffic surges (e.g., Diwali, Karwa Chauth, New Year), and rapid promotional banner transitions.

1.1 Mission-Critical Engineering Challenges

⚡ Sub-Second Browsing Latency

Shoppers browsing 50+ catalog brands and thousands of cosmetic variations expect immediate response times (< 200ms p95). Querying raw disk databases on every catalog page load causes unviable latency and database CPU exhaustion.

🔒 Zero Overselling & Financial Invariants

During flash sales, hundreds of shoppers attempt to checkout the exact same limited-stock item simultaneously. The platform must mathematically prevent double-spending and overselling without locking the entire database.

📨 Non-Blocking Async Workflows

Order placement triggers transactional emails (Resend), SMS notifications, warehouse push alerts, and audit streaming. These third-party dependencies must never block the customer's checkout completion.

🎨 Decoupled Editorial & Marketing Velocity

Marketing teams require instant autonomy to launch promotional campaigns, hero carousels, and skincare editorial routines through a headless CMS without requiring frontend redeployments or engineering PRs.

2 Deep-Dive: Architectural Technology Justifications

Every infrastructure component in the ShagunShopping architecture addresses a specific bottleneck in high-scale e-commerce systems. Below is the precise justification for each technology selection.

2.1 Apache Kafka (KRaft Mode): The Event-Driven Backbone

In traditional monolithic e-commerce platforms, when a shopper clicks "Confirm Order", the backend synchronously connects to the payment gateway, deducts inventory, calls an external email API, sends a WhatsApp alert, and triggers warehouse logistics.

⚠️ The Synchronous Checkout Anti-Pattern
If Resend email API experiences 4 seconds of network jitter, the customer's browser spins. If the email API crashes entirely, the entire checkout transaction fails, resulting in cart abandonment and revenue loss.

What Apache Kafka does in ShagunShopping:

  • Asynchronous Decoupling: The Express API creates the order, dispatches a persistent event (order.created or payment.captured) to Kafka within 2 milliseconds, and immediately returns HTTP 201 Created to the user.
  • Durable Replayability & Fault Tolerance: Kafka writes events to append-only disk segments replicated across partitions. If the notification service or email worker goes down for maintenance, it resumes from its exact consumer offset upon reboot with zero message loss.
  • Peak Traffic Smoothing (Backpressure Buffer): During sudden traffic spikes (e.g., 10,000 orders in 60 seconds), Kafka absorbs the surge safely, allowing background workers to process notifications and warehouse dispatches at a controlled, steady pace without crashing downstream systems.
  • KRaft Consensus (No ZooKeeper): Apache Kafka 3.7+ operates in KRaft mode (Kafka Raft), managing its own metadata quorum natively. This eliminates the operational fragility, network overhead, and memory consumption of managing a separate ZooKeeper cluster.

2.2 Redis 7.2 (Alpine): Distributed In-Memory Store & Locks

MongoDB is optimized for rich document storage and durability on SSDs, but reading from disk takes 5–25ms. Redis operates entirely in RAM, executing queries in sub-millisecond latencies (0.2–0.8ms).

What Redis does in ShagunShopping:

  • Distributed Inventory Locking (Redlock / Atomic SETNX): When multiple users race to purchase the final unit of a product, Redis acquires an atomic lock: SET lock:inventory:<productId> <uuid> NX PX 3000. Only the thread holding the lock executes stock validation, completely eliminating race conditions.
  • Read-Through Catalog Caching: Product listings (/api/products), category taxonomies, and marketing banners are cached in Redis. 92% of browsing traffic is served directly from RAM without touching the primary database.
  • Idempotency for Payment Webhooks: Razorpay delivers webhook events under an at-least-once guarantee (potential duplicate deliveries). Redis stores webhook:idempotency:<event_id> with a 24-hour TTL, ensuring payments are never processed twice.
  • Distributed Sliding-Window Rate Limiting: Enforces token buckets across auth endpoints (preventing brute-force attacks on OTP and login) and cart additions across distributed instances.

2.3 Docker & Docker Compose: Immutable Containerization

Software development historically suffered from the "works on my machine" discrepancy—discrepancies between macOS arm64 development machines and Linux x86 production servers, different Node.js minor versions, missing system libraries, and divergent database configurations.

What Docker does in ShagunShopping:

  • Immutable Artifacts: The application code, Node.js 20 runtime, security certificates, and OS dependencies are packaged into lightweight, hardened container images (e.g., Alpine Linux).
  • Multi-Stage Builds: The Dockerfile compiles dependencies and TypeScript/Vite bundles in a temporary builder stage, then copies only the minimal production artifacts into a hardened runner container executed by an unprivileged system user (USER node).
  • Local Orchestration (Docker Compose): Standardizes the entire 7-tier stack (Frontend, Backend, Mongo, Redis, Kafka, Kafka-UI, CMS) into a single declarative file (docker-compose.yml), establishing isolated bridge networks, health probes, and persistent volumes locally with one command: docker compose up -d.

2.4 Kubernetes (K8s): Production Elasticity & Self-Healing

Docker Compose is designed for single-node development. In production, running an enterprise store on a single server introduces a catastrophic Single Point of Failure (SPOF). If that virtual machine reboots or crashes, the entire store goes offline.

What Kubernetes provides in ShagunShopping:

  • Horizontal Pod Autoscaler (HPA): Continuously monitors CPU and memory consumption. When traffic surges during an ad campaign, K8s automatically scales backend pods from 2 to 10 instances in seconds, scaling down when traffic subsides to optimize cloud spend.
  • Automated Self-Healing: K8s continuously checks container health via HTTP livenessProbe and readinessProbe endpoints. If a pod deadlocks or experiences an unhandled memory leak, K8s terminates it and spins up a replacement instantly.
  • Zero-Downtime Rolling Updates: When deploying a new release, Kubernetes spins up new version pods, verifies they pass health checks, smoothly redirects incoming traffic, and terminates old pods without a single dropped customer connection.
  • Ingress & TLS Management: Routes traffic based on host and path rules (/api/* to Backend pods, / to Frontend Nginx, /admin to CMS), terminating SSL/TLS certificates automatically with Let's Encrypt.

2.5 MongoDB 7.0 & Strapi Headless CMS

  • MongoDB 7.0 (ACID Transactions): Cosmetics and beauty products require flexible schema structures (varying shades, botanical ingredients, skin type suitability, safety labels). MongoDB provides document flexibility combined with multi-document ACID transactions (session.startTransaction()) for checkout operations.
  • Strapi Headless CMS: Separates dynamic promotional content from core commerce code. Marketing teams update homepage hero banners, discounts, and editorial skincare rituals independently, exposed via secured REST endpoints with fallback resilience.

3.1 Architectural Domains & Bounded Contexts

  • Storefront & Edge Domain: Handles client requests, edge SSL offloading, asset minification, and static routing via Nginx and Vercel CDN.

4.2 Financial Integrity & Pricing Invariants

The order calculation engine strictly enforces financial consistency at the model schema level. Requests with client-tampered totals are immediately rejected.

totalPrice === itemsPrice + shippingPrice + codFee
• itemsPrice = Σ (item.price * item.quantity)
• shippingPrice = 0 if itemsPrice >= FREE_SHIPPING_THRESHOLD, else ₹49
• sellingPrice must always be <= MRP (Schema-enforced validation)

6 Resilience, Security & Disaster Recovery

6.1 Defense-in-Depth Security Matrix

  • Cloudflare Turnstile Verification: Protects checkout and authentication endpoints from automated bot spam without visual user friction.
  • NoSQL Injection Prevention: express-mongo-sanitize strips out prohibited characters (e.g., $, .) from request bodies and query parameters.
  • HTTP Security Hardening: Helmet sets strict Content-Security-Policy, X-Content-Type-Options: nosniff, X-Frame-Options: SAMEORIGIN, and Strict-Transport-Security.
  • Cryptographic Signature Verification: Razorpay webhook payloads are authenticated using crypto.createHmac('sha256', secret) before updating order payment states.
  • Unprivileged Container Execution: Backend runs under unprivileged USER node (UID 1000) inside containers to prevent host root-escalation attacks.
